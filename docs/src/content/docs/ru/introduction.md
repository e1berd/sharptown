# Введение

**Sharptown** — это высокопроизводительный сервис трансформации и конвертации изображений
на базе [Fastify](https://fastify.dev) и [Sharp](https://sharp.pixelplumbing.com) (libvips).
Он позволяет **изменять размер, поворачивать, размывать, обесцвечивать, тонировать,
управлять альфа-каналом и конвертировать форматы** — всё на лету через простой API.

## Почему Sharptown?

Главная цель проста: **превращать изображения в оптимизированный формат** — например
`webp` или `avif` — чтобы они передавались меньшим числом байт.

Иными словами, основное назначение — **оптимизация доставки изображений**:

- Меньше объём → быстрее загрузка страниц и лучше Core Web Vitals.
- Ниже расходы на трафик и CDN.
- Современные форматы (WebP, AVIF, HEIF) без необходимости менять исходные файлы.
- Трансформации по запросу: вы храните один оригинал и порождаете любые варианты.

> Загрузите тяжёлый `.jpg`, запросите `?width=800&convertTo=webp` — и получите небольшое,
> готовое для веба изображение. Именно для этой повседневной задачи и создан Sharptown.

## Больше, чем конвертер: постройте полноценный фоторедактор

Оптимизированная доставка — это фундамент, но не потолок.

Поскольку Sharptown поставляется с **запущенным сервером** и выразительными
**клиентами на JavaScript, PHP, Go и Elixir**, у вас есть всё необходимое, чтобы построить
поверх него **полноценный фоторедактор прямо в браузере** (или серверный конвейер обработки
изображений):

- Браузер отправляет изображение пользователя и цепочку операций на запущенный сервер
  Sharptown.
- Сервер выполняет тяжёлую работу с пикселями с помощью Sharp и отдаёт результат потоком.
- Ваш интерфейс показывает живое превью, позволяет менять параметры и экспортировать
  итоговое изображение.

Так что Sharptown может быть сразу двумя вещами:

1. **Оптимизатором в стиле CDN** перед доставкой ваших изображений.
2. **Бэкенд-движком настоящего редактора**, где resize/blur/tint/convert становятся
   инструментами редактирования.

Подробный пример — в разделе [Как построить фоторедактор](/ru/docs/building-an-editor).

## Что внутри

| Пакет | Роль |
| ----- | ---- |
| `@sharptown/core` | Движок на Sharp, не зависящий от фреймворка; используется всеми адаптерами. |
| `@sharptown/fastify-plugin` | Плагин Fastify с маршрутом `POST /transform`. |
| `@sharptown/client` | Выразительный изоморфный JS-клиент (браузер / Node / Bun / Deno). |
| `@sharptown/server-rest` | REST-хост (Fastify + плагин + статический UI). |
| `@sharptown/server-grpc` | gRPC-хост с двунаправленным стримингом. |
| `@sharptown/server-jsonrpc` | Хост JSON-RPC 2.0 поверх WebSocket. |

Три транспорта, **один общий движок**. Выберите тот, что подходит вашему стеку, — или
запустите все три сразу.

## Клиенты

Один и тот же цепочечный API доступен на нескольких языках. **В реестр пакетов (npm)
опубликован только JavaScript-клиент.** Клиенты на PHP, Go и Elixir лежат в этом
репозитории в `clients/<язык>` и устанавливаются прямо из GitHub.

| Клиент | Язык | Транспорты | Установка |
| ------ | ---- | ---------- | --------- |
| [JS](/ru/docs/js-client) | JavaScript — браузер, Node, Bun, Deno | REST | `npm i @sharptown/client` (npm) |
| [PHP](/ru/docs/php-client) | PHP ≥ 8.1 | REST, JSON-RPC | Composer path-репозиторий из репо (не Packagist) |
| [Go](/ru/docs/go-client) | Go | REST, JSON-RPC, gRPC | `go get …/clients/go` (из GitHub) |
| [Elixir](/ru/docs/elixir-client) | Elixir (OTP 27+) | REST, JSON-RPC | Mix git-зависимость (не Hex) |

Поддержка gRPC в PHP- и Elixir-клиентах в работе.
