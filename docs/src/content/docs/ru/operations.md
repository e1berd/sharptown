# Справочник операций

Каждый транспорт принимает **один и тот же набор операций** — все они проходят через
`applyOperations` в `@sharptown/core`. Эта страница — единый источник истины о том, что
делает каждый параметр. Все операции здесь **потоково-безопасны** (работают через
gRPC-стрим), поэтому доступны одинаково в REST, gRPC и JSON-RPC.

## Размер и кадрирование

| Параметр | Тип | Диапазон / значения | Действие |
| -------- | --- | ------------------- | -------- |
| `width` | число | ≥ 0 | Ширина изменения размера, в пикселях. |
| `height` | число | ≥ 0 | Высота изменения размера, в пикселях. |
| `dpr` | число | `0.1`–`5` | Device pixel ratio; умножает целевые ширину/высоту. |
| `aspectRatio` | число | > 0 | Целевое соотношение (например, `1.7778`). Нужен `width` или `height`. |
| `fit` | строка | `cover` `contain` `fill` `inside` `outside` | Режим вписывания при ресайзе. |
| `background` | строка | цвет | Фон для `contain` (например, `white`, `#000`, `rgba(0,0,0,0)`). |
| `smartCrop` | булево | — | Обрезка к самой значимой области (лица/контраст) при ресайзе. |
| `crop` | строка | `x,y,w,h` или `WxH` | Прямоугольник обрезки или размер вместе с `cropOffset`. |
| `cropOffset` | строка | `x,y` | Смещение для формы `WxH`. |
| `autoOrient` | булево | — | Поворот по тегу ориентации EXIF. |
| `rotate` | число | градусы | Поворот на N градусов. |
| `flip` | булево | — | Отражение по горизонтали. |

`smartCrop` и `aspectRatio` по умолчанию ставят `fit: cover` (обрезают под целевой
размер). `crop` принимает две формы: полный прямоугольник `crop=10,20,300,200` или размер
с отдельным смещением `crop=300x200&cropOffset=10,20`.

## Тон и цвет

| Параметр | Тип | Диапазон | Действие |
| -------- | --- | -------- | -------- |
| `brightness` | число | `-100`–`100` | Яркость. |
| `contrast` | число | `-100`–`100` | Контраст. |
| `saturation` | число | `0`–`2` | Насыщенность (`1` — оригинал). |
| `exposure` | число | `-3`–`3` | Экспозиция в стопах EV. |
| `hue` | число | `0`–`360` | Сдвиг оттенка в градусах. |
| `gamma` | число | `1.0`–`3.0` | Гамма-коррекция. |
| `colorize` | строка | цвет | Перевод в оттенки одного цвета (greyscale + tint). |
| `r`, `g`, `b` | число | `0`–`255` | Тонирование по каналам. |
| `grayscale` / `greyscale` | булево | — | Обесцвечивание. |

## Фильтры и эффекты

| Параметр | Тип | Диапазон | Действие |
| -------- | --- | -------- | -------- |
| `blur` | число | ≥ 0 (сигма) | Размытие по Гауссу. |
| `sharpen` | число / булево | `0`–`5` | Резкость (сигма); truthy без значения — значение по умолчанию. |
| `sepia` | число / булево | `0`–`1` | Интенсивность сепии; truthy — полная сепия. |
| `invert` | булево | — | Инверсия цветов. |
| `threshold` | число | `0`–`255` | Бинаризация в ч/б по порогу. |
| `oilPaint` | число | `1`–`25` | Эффект масляной краски через медианный фильтр (размер окна). |

## Альфа и вывод

| Параметр | Тип | Диапазон / значения | Действие |
| -------- | --- | ------------------- | -------- |
| `removeAlpha` | булево | — | Убрать альфа-канал. |
| `ensureAlpha` | булево | — | Гарантировать альфа-канал. |
| `convertTo` | строка | см. ниже | Формат вывода. |
| `quality` | число | `1`–`100` | Качество вывода (действует при перекодировании через `convertTo`). |
| `progressive` | булево | — | Прогрессивный (чересстрочный) JPEG/PNG. |
| `stripMetadata` | булево | — | Удалить EXIF/профили. По умолчанию удаляется; `false` — сохранить. |

> Через транспорт REST каждое значение приходит как строка запроса, поэтому булевы — это
> буквальные строки `"true"` / `"false"`, а числа — строки. Клиент и ядро нормализуют это
> за вас.

## Поддерживаемые форматы вывода

`convertTo` должен быть одним из:

```
webp · png · jpg · jpeg · avif · gif · heif
```

Что-либо иное порождает `InvalidOperationError` → HTTP `400` (`"Invalid convert format
target"`). `quality` и `progressive` действуют при перекодировании изображения (то есть с
`convertTo`). Если опустить `convertTo`, изображение сохраняет исходный формат, а заголовок
`Content-Type` в ответе всё равно отражает то, что фактически произвёл Sharp.

## Порядок операций

`applyOperations` применяет шаги в фиксированном, разумном порядке независимо от того, как
вы их перечислили:

1. `autoOrient`
2. `crop`
3. `removeAlpha` / `ensureAlpha`
4. `colorize`
5. тонирование (`r` / `g` / `b`)
6. `brightness` / `exposure` / `saturation` / `hue`
7. `contrast`
8. `gamma`
9. `grayscale`
10. `sepia`
11. `invert`
12. `threshold`
13. `blur`
14. `sharpen`
15. `oilPaint`
16. `flip`
17. `rotate`
18. ресайз (`width` / `height` / `dpr` / `aspectRatio` / `fit` / `background` / `smartCrop`)
19. `convertTo` (с `quality` / `progressive`)
20. `stripMetadata`

## Правила валидации

- `width`, `height`, `blur` должны быть **неотрицательными целыми**.
- `r`, `g`, `b` должны быть целыми в диапазоне **`[0, 255]`**.
- Диапазонные значения (`brightness`, `contrast`, `saturation`, `exposure`, `hue`,
  `gamma`, `sepia`, `threshold`, `sharpen`, `oilPaint`, `quality`, `dpr`) сервер
  ограничивает (clamp) их документированным диапазоном; клиент отклоняет значения вне
  диапазона заранее.
- `fit` — один из перечисленных режимов; `convertTo` — один из поддерживаемых форматов.
- `aspectRatio` требует `width` или `height`.
- Значения вне диапазона или нечисловые порождают `InvalidOperationError`. Клиент проверяет
  их **до** отправки запроса, мгновенно падая с `SharptownError`.

## Лимиты для больших файлов (стриминг / gRPC)

При обработке очень больших изображений помните о пиксельных лимитах форматов вывода:

- **WebP** — до `16383 × 16383` px.
- **JPEG** — до `65535 × 65535` px.

Если карта превышает лимит WebP, конвертируйте в JPEG или примените `resize` в том же
запросе. Для гигабайтных входов предпочитайте `resize` / `convert` / `flip`; произвольный
`rotate` может потребовать больше памяти.
